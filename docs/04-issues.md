# Issues

An **issue** is a place to discuss ideas, report bugs, plan features, or keep track of anything that needs attention in a repository. Issues are free-form conversations tied to your project.

## Create an issue

1. Open your repository on GitHub.
2. Click the **Issues** tab at the top.
3. Click **New issue**.
4. **Title:** Write a short, clear title. Example: "Fix typo on About page."
5. **Description:** Describe the problem or idea. Include:
   - What you expected to happen
   - What actually happened
   - Steps to reproduce, if it is a bug
   - Screenshots (optional — drag them into the box)
6. Click **Submit new issue**.

## Assign labels

Labels help you sort issues. Common labels:

- `bug` — something is broken
- `enhancement` — a new feature idea
- `documentation` — the docs need work
- `good first issue` — easy enough for a new contributor

To add labels, click the **Labels** gear icon on the right side of the issue page and pick ones that fit.

## Assign people

You can assign an issue to yourself or to a collaborator. Click the **Assignees** gear icon and choose who is responsible for the work.

## Close an issue

When the work is done:

1. Open the issue.
2. Click **Close issue** at the bottom.

The issue stays in the history with a "closed" status, so anyone can see what was resolved and when.

## Reopen an issue

If a closed issue comes back, open it and click **Reopen issue**.

## Link issues to commits and pull requests

When you write a commit message or pull request, you can reference an issue by typing `#` followed by the issue number (for example, `#12`). GitHub links them together automatically.

## What's next

Issues track what needs to change. Pull requests are how you actually propose and review those changes.
