# Releases

A **release** is a packaged version of your project that people can download. Releases are useful when you want to share a finished version — for example, version 1.0 of a guide, a template, or a small tool.

## Create a release

1. Open your repository on GitHub.
2. Click the **Releases** link on the right side of the page (or click **Code** > **Tags** > **Releases**).
3. Click **Draft a new release**.
4. **Tag version:** Type a version number. Tags mark specific points in history. Common formats:
   - `v1.0`
   - `v1.0.1`
   - `2026-10-27`
5. **Target:** Choose `main` (the branch to release from).
6. **Release title:** A name for the release, like "Version 1.0 — First release."
7. **Describe this release:** Write what is new or changed. Example:

   ```
   ## What's New

   - Initial release of the beginner GitHub guide
   - Includes account setup, repos, and Pages publishing
   ```

8. **Attach files (optional):** Drag files you want people to download, such as a PDF or ZIP.
9. **Set as the latest release:** Leave checked if this is the current version.
10. **Create as a pre-release:** Leave unchecked unless this is a test version not meant for general use.
11. Click **Publish release**.

## What people get

Published releases get their own page on GitHub, with a list of assets people can download. Each release is tied to a tag, so you can always go back and see exactly what code the release contained.

## Edit or delete a release

1. Go to the Releases page.
2. Click the release you want to change.
3. Click **Edit release** to change the title, description, or attachments.
4. To delete, click **...** > **Delete release**.

Deleting a release does not delete your code or tags — it only removes the release page and attachments.
