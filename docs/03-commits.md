# Commits

A **commit** is a saved snapshot of your repository. Every time you save changes on GitHub, you create a commit. Commits build a timeline of your project, so you can look back at any earlier version.

## What a commit contains

Each commit records:

- **The commit message** — a short description of what changed.
- **The author** — who made the change.
- **The date and time.**
- **The files changed** — what was added, edited, or deleted.
- **A unique ID** — a long string of letters and numbers (for example, `a1b2c3d`).

## View the commit history

1. Open your repository on GitHub.
2. Click the **commits** link near the top of the page (it shows a number, like "3 commits").
3. You see a list of every commit, newest first.
4. Click any commit to see exactly what changed in it.

## Write good commit messages

A good commit message tells the story of the change:

- Use the present tense: "Add about page," not "Added about page."
- Keep the first line under 50 characters if you can.
- Add details below if the change is complicated.

Examples:

| Instead of | Try |
|---|---|
| update | Update README with contact info |
| fixed stuff | Fix broken link in navigation |
| changes | Add privacy policy and terms |

## Compare two versions of a file

1. Open a file in your repository.
2. Click the **History** button (clock icon).
3. Click any commit to see that version.
4. To compare two commits, click the **...** menu on one commit and choose **Compare with branch**, or open two commits side by side in your browser.

## Undo a mistake

GitHub keeps every commit, so mistakes are rarely permanent:

- **Revert a commit:** On the commits page, open the commit, click **...**, and choose **Revert commit**. GitHub creates a new commit that undoes the changes. Your history stays intact.
- **Restore a deleted file:** Open the commit that deleted the file, click the file name, then click **View file** and save it again in a new commit.
