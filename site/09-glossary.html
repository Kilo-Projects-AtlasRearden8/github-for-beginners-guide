Glossary

Plain-English definitions of GitHub terms used in this manual.

Account — Your personal profile on GitHub. You need one to create repositories, comment on issues, and open pull requests.

Branch — A separate workspace for changes. Branches keep work isolated until it is ready to join the main project.

Commit — A saved snapshot of a repository. Each commit records who changed what, when, and why.

Commit message — A short description written with every commit, explaining what changed.

Diff — A side-by-side view showing what changed between two versions of a file. Removed lines are shown in red; added lines in green.

Fork — A personal copy of someone else's repository. Not covered in detail in this manual, but useful if you want to experiment with someone else's project.

Issue — A discussion thread in a repository used to track bugs, ideas, tasks, or questions.

License — A legal statement that tells others what they can and cannot do with your code or content. This manual uses the MIT License.

Main (branch) — The default primary branch of a repository. It usually holds the stable, published version of a project.

Merge — Combining changes from one branch into another, usually through a pull request.

Pull request (PR) — A proposal to change a repository. Others review the changes before they are merged.

Push — Uploading commits from your computer to GitHub. This manual avoids the command line, so you will not need to push manually; saving on GitHub does it for you.

README — The front-page file of a repository, usually named README.md. It explains what the project is and how to use it.

Release — A packaged, tagged version of a project that people can download.

Repository (repo) — A project folder on GitHub that holds files and their complete history.

Static site — A website made of HTML, CSS, and JavaScript files, with no server-side code. GitHub Pages hosts static sites for free.

Tag — A label marking a specific point in a repository's history, often used for releases (for example, v1.0).

Two-factor authentication (2FA) — An extra login step that protects your account, usually with a code from your phone or an app.

Workflow — The repeated steps you follow on GitHub: create, edit, commit, review, publish.
